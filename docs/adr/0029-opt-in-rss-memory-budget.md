# ADR 0029：RSS 预算改为显式配置，默认优先可用性与热态复用

- 日期：2026-10-29。
- 状态：**Proposed；维护者已明确决定并授权实施，已实现/验证（fast2096/2096、Windows所选24项及生命周期2项）；不伪造额外审阅记录或Accepted状态**。
- 父版本：`9d47e550ee7c0a3ba9e0e889f62e04bb9fd4a78a`；保留已有缓存治理工作树。
- 证据：[此前调查](../reports/2026-10-29-memory-pressure-and-worker-release.md)、
  [本轮TDD](../tdd/2026-10-29-opt-in-rss-memory-budget.md)。

## 问题与优先级

整个Node进程RSS并不等于某个Program的可释放内存：主线程、语义/验证/诊断isolate、
native/external及分配器保留页共同影响它。固定4GiB预算可能在查询仍可完成时触发L2/L3，
销毁热LS/Program，转入冷验证、临时诊断，或拒绝完整范围请求；RSS未必随dispose立即下降。
连续查询可能因此重复构建。已有4GiB决策是运行期压力策略，不是V8或进程RSS硬上限。

维护者明确的产品顺序：**功能可用、响应快、运行稳定，之后才是内存占用低**。
默认不因一个产品自定RSS阈值牺牲完整结果与有效热状态；也不把工作集增长等同于泄漏。

## 决定

1. `defaultMemoryBudgetMiB:null`，未设置`ARKTS_MEMORY_BUDGET_MB`时，runtime的
   `memoryBudgetBytes`为null，表示没有产品RSS预算；不是Infinity、调大数字或另加隐藏阈值。
2. 此模式RSS策略始终返回L0，不由RSS触发trim、驱逐、压力准入拒绝、切换临时诊断，
   或发送主动Worker压力替换事件。RSS/heap观察保留，不把无预算变成无观测。
   L01/L03功能开关可继续存在，只有显式预算产生真实压力等级时才驱动相应自动路线。
3. 显式配置正数仍按MiB转换，沿用原分级、L3滞回、活动lease保护、首次准备豁免和完整性约束。
   空串/空白、0、负数、NaN/Infinity及无法表示有效字节预算的输入报配置错误；不悄悄当作无限。
   不新增`off`/`auto`字符串别名；取消已配置预算应删除环境变量，再建立新语言服务会话。
4. 没有默认RSS预算不代表“不清理”：配置/SDK域替换、失效owner、项目/会话dispose、
   请求/取消/失败的lease结清、临时verifier job收尾及现有有界memo规则保留。
   稳定语义组身份不随光标、请求或普通内容版本变化；不按次数、固定空闲TTL或另一个默认容量强制重建。
5. 继续保留单个主语义Worker、串行重型任务、有限恢复预算/退避/熔断、旧世代隔离、
   文档权威、配置重放、输入新鲜度及完整作用域。内存压力关闭不关闭故障监督。
6. V8默认/用户配置的堆上限和系统OOM机制保持原样；不加堆参数，不吞OOM，
   不把线程/进程崩溃重标为正常清理。不宣称取消预算已经修复30K OOM或任意大工作集都能运行。
7. 磁盘索引缓存治理独立，由[ADR0028](0028-index-cache-lifecycle.md)管理；
   不把产品RSS预算、磁盘容量、旧release回收与此前2048MiB测试驱动停测线混为一项。

## 修订关系

- 明确替代ADR0018的“默认4GiB”及ADR0019中默认由压力决定驻留的部分；
  预算显式配置时，其分级/滞回/活动保护合同继续有效。
- ADR0015的完整resident复用等默认不撤销；压力相关自动路线在无预算时不因RSS生效。
- ADR0020等故障恢复、ADR0025–0027新鲜度/取消/调度约束及历史失败证据保留，不作回溯改写。
- 文件大小、项目成员、请求消息及memo的既有限制不是RSS预算，本轮不放宽；
  超出完整性边界仍须明确失败，不能返回截断成功。30K完整引用/重命名等缺口仍存在。

## 备选与取舍

- 拒绝只把4GiB调大：仍是同一隐式默认降级机制，不能证明适合用户实际工作集。
- 不替换成系统剩余内存百分比、按项目文件数估计或新的TTL/固定Program数：
  本轮没有跨平台、负载归属和响应体验证据，不能新增另一种默认驱逐触发。
- 不删除显式预算能力：资源受限环境可主动选择，用同一套完整性与执行保护约束运行。
- 不采用“默认永不释放”：正常所有权生命周期及有界缓存保留，避免旧版本/失效状态无界积累。

代价是合法工作集可保留更多内存，且未提供产品RSS封顶。更大的真实依赖闭包、多个实际语义组
仍可能接近V8/系统资源限制；需要独立规模/内存验证，不凭较低RSS或未崩溃宣称稳定。

## 可验证的验收

- 真实framed stdio LSP在未配置预算、受控报告RSS高于原4GiB时，保持完整READY、精确查询、
  热Program复用、编辑撤销/关闭重开及最新未保存内容，不发生RSS驱逐/重启循环。
- 同一输入和受控RSS下显式预算仍触发原有压力语义，错误配置明确拒绝。
- 混合热态循环的owner/Program创建计数不按请求次数增长；配置替换/故障/关闭后资源所有权结清。
  记录真实RSS/heap与受控输入分别为何，不将合成RSS当作实际8GiB压测。
- 复用并运行取消、故障恢复、SDK域替换、缓存治理及完整结果回归；
  最终候选执行`pnpm check:fast`，保留逐次失败和完整通过证据。
- 500ms是允许波动的体验目标，不新增硬时延门禁；455冷目录性能项沿用既有授权豁免。
  不提交/合并/发布/部署、不重启用户进程，除非获得新的明确指示。

## 实施收据

本候选已通过完整`pnpm check:fast`2096/2096（失败/跳过/取消/TODO均0），
Windows协调器21/21、所选公开LSP3/3及独立生命周期诊断2/2；
[实施报告](../reports/2026-10-29-default-unbudgeted-memory.md)与TDD保留命令、SHA、
默认/显式预算对照、真实compiler构建计数及资源结清证据。
这是私有SDK与受控RSS验证，未重新执行30K真实UI或实际8GiB工作集耐久；
不将原生455文件冷目录3秒授权豁免写成通过，不提交、部署或合并。
