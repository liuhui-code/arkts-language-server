# ADR 0007：首次语义准备与就绪后 500 ms 契约

日期：2026-09-29。状态：**Requirement-confirmed；本次仅记录用户产品要求**。

## Context

用户允许首次打开时充分准备，但要求语义就绪后的新符号、跨模块、普通编辑及回收恢复查询保持快速。R-20 的候选索引等待和少数完整答案缓存不能代表语义就绪。

## Decision

- 首次语义准备的时间、进度、取消与资源独立报告；准备期间仍受原内存门禁。
- `ready` 必须绑定能力、完整语义覆盖和有效输入版本；候选索引已提交、一个常驻 Program 或已缓存基准答案均不足以声明 ready。
- 就绪后按能力和场景分别验证完整响应 P95 ≤500 ms。计时包含排队、增量更新等待、磁盘读取、回退、合并及序列化。
- 普通编辑的 `updating`、首次查询新符号/新模块、驱逐后的重建及有效持久状态的重启恢复查询均计入该目标，不能重新标成首次准备。
- SDK、target 或大型分支变化可单列重新准备；尚未完成的能力如实标为 partial/degraded，不能据此宣称整体验收完成。

## Consequences and gate

准备可比旧目标更充分，但不是无限预热或资源豁免。正确性、readiness、分桶时延及内存须联合通过，才能宣传目标完成。只统计缓存命中会漏掉新符号和编辑后的体验；仅保留巨大 Program 也不能证明低内存。

样本、能力、硬件和工具链在测量前冻结。无法在预算内就绪时记录失败并保持 degraded；改变需求范围须新决策，不能修改测量分母。
