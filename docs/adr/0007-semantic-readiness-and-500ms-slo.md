# ADR 0007：首次语义准备与就绪后500ms体验目标

日期：2026-09-29。状态：**Requirement-confirmed；本次仅记录用户产品要求**。

## 2026-10-28 用户确认的时延口径修订

500ms为性能/体验目标，允许适当波动；单次或偶发超过目标不独立判功能失败、不单独阻塞交付。
结合典型操作、分布、超目标频率、连续性和持续性判断；持续严重慢响应、超时、错误结果及不可用仍如实记录。
不新增硬数值、比例或持续时长阈值；下文2026-10-10的550ms/P95为历史合同，本轮不作为替代硬线。
保留旧测量和当时判定，不自动追认性能通过；其他正确性/生命周期/执行截止不变。
具体评估及旧自动化边界见[当前时延评估](../benchmarks/interactive-latency-assessment.md)。

2026-10-18：维护者通过 [ADR 0018](0018-semantic-groups-and-initial-preparation.md) 明确首次项目初始化不受压力值约束；运行期默认压力 4GiB，可配置。下文首次准备受预算限制的旧条款由该决定替代；当前优化仍按维护者要求验证就绪后 500ms，不重标旧测量结论。

## Context

用户允许首次打开时充分准备，但要求语义就绪后的新符号、跨模块、普通编辑及回收恢复查询保持快速。R-20 的候选索引等待和少数完整答案缓存不能代表语义就绪。

## Decision（历史条款；当前时延解释以上述修订为准）

- 首次语义准备的时间、进度、取消与资源独立报告；准备期间仍受原内存门禁。
- `ready` 必须绑定能力、完整语义覆盖和有效输入版本；候选索引已提交、一个常驻 Program 或已缓存基准答案均不足以声明 ready。
- 就绪后按能力和场景分别验证完整响应；500 ms 为优化目标，2026-10-10 用户明确确认 L08 正式验收上限为 P95 ≤550 ms。计时包含排队、增量更新等待、磁盘读取、回退、合并及序列化。
- 普通编辑的 `updating`、首次查询新符号/新模块、驱逐后的重建及有效持久状态的重启恢复查询均计入该目标，不能重新标成首次准备。
- SDK、target 或大型分支变化可单列重新准备；尚未完成的能力如实标为 partial/degraded，不能据此宣称整体验收完成。

## Consequences and gate（历史数值门禁记录）

本次用户授权仅调整时延上限；每格 ≥100 请求/≥5 独立会话、完整正确性、
真实 ready、原内存、生命周期和三平台门槛不变。历史 500 ms 失败不改写，
旧构建不自动认证为新口径 PASS；新实测分别报告超过 500/550 ms 的样本。

准备可比旧目标更充分，但不是无限预热或资源豁免。正确性、readiness、分桶时延及内存须联合通过，才能宣传目标完成。只统计缓存命中会漏掉新符号和编辑后的体验；仅保留巨大 Program 也不能证明低内存。

样本、能力、硬件和工具链在测量前冻结。无法在预算内就绪时记录失败并保持 degraded；改变需求范围须新决策，不能修改测量分母。
