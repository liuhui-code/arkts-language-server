# ADR 0018：初始化准备、稳定语义组与延迟释放

- 日期：2026-10-18。
- 后续：[ADR 0019](0019-stable-programs-and-request-inputs.md) 明确修订固定“两组＋一槽”为压力管理驻留，并收紧 degraded 首次准备边界；实施与性能验收进行中，下文保留原决定和历史证据。
- 状态：维护者明确授权，Accepted；实现按 TDD 切片推进，性能尚未验收。
- 设计：[完整方案](../plans/2026-10-18-semantic-group-lifecycle-design.md)。维护者在审阅后修订压力值与初始化约束；下述决定优先于草案中的旧参数。

## 决定

1. 默认压力预算为 **4GiB（4096MiB）**，支持现有 `ARKTS_MEMORY_BUDGET_MB` 配置；保留压力分级与滞回。预算是运行期压力策略，不宣称 RSS 硬上限。
2. **项目首次初始化全过程不受配置压力值约束**。SDK/标准库预解析、项目发现、初始语义组与依赖准备期间继续采集真实内存，但不因该压力值驱逐、trim 或拒绝准备。取消、关闭、输入新鲜度和错误处理仍有效。后续普通编辑、查询、新组切换及驱逐恢复不重新冒充首次初始化；运行阶段恢复压力策略。
3. 服务端在项目初始化主动准备实际查询 owner 内的共享 SDK/标准库缓存。兼容声明长期复用，SDK 与不兼容配置改变时刷新；预解析不扩大 Program 根集合或 ambient 作用域。
4. 按真实 workspace/product/module/target、编译选项与 SDK 身份定义稳定语义组。内容版本、查询光标和候选列表不改变组身份；相关编辑更新现有 LS 与合法未变状态。
5. 近期交互组与串行扫描槽保留 LS/Program。请求结束归还 lease；容量、压力、失效或项目关闭触发实际释放。活动保护后按 LRU 管理近期组，后台扫描不污染交互近期性。初版两个交互组、一个串行扫描槽共享运行期预算，不并行扩张重型编译。
6. 全局引用仍须证明全部合法搜索范围；索引提供候选，官方 compiler 决定最终语义。跨组、ambient、overlay、依赖闭包、版本与发布前 fence 不因复用而削弱。
7. 首次准备耗时单列；就绪后未查询符号、普通编辑、切换及恢复的完整响应目标保持 **500ms**。不以缓存命中或延后发请求证明达标。

## 对既有 ADR 的修订

- 修订 ADR 0007/0014 中首次准备也受压力预算的限制，以及 ADR 0015 的 1024MiB 默认；运行期完整性、取消与压力恢复保留。
- 修订 ADR 0016/0017 的逐 job 项目 LS 销毁与项目 Registry leases 必须始终为零要求。允许已准入上下文保留项目 leases；请求归还 lease，实际驱逐后验证该上下文所有权释放。SDK 与项目 lease 分别计数。
- 调整 ADR 0015 的成本优先驱逐为活动保护后的近期 LRU；重建成本继续观测。
- 按功能切片逐步替换；迁移中未覆盖的路线保持现有完整安全回退，不把部分实现标成全部完成。

## 当前实现边界

正常预算的生产路径已接入初始化 SDK catalog、标准库和前两个模块组预建，完整范围 owner 负责全局查询；配置恢复在兼容 owner 内重新准备，复用 SDK。未配置或依赖图不完整的工程保持完整 workspace 安全范围，不用文件数量推测构建模块。固定 compiler/SDK 配置域内的组 ID 不随内容变；配置替换先销毁旧域，因此不会把旧 Program 冒充新配置。

后台诊断只复用已驻留交互组且不提升交互 LRU；冷后台任务使用扫描槽。请求归还 lease 不销毁 LS。压力恢复每次释放后重新读取真实压力，达到滞回目标就停止。稳定组只有持完整连续磁盘 delta 证据时增量复用，未知变更保守重建。

压力触发的隔离分批回退，以及显式关闭 resident 复用的基线比较路径，继续使用原 verifier 的及时释放规则；这些未迁移的控制路径不能宣称共享 owner 或取得 500ms 全矩阵资格。两次真实 SDK 403 文件、就绪后共 208 次查询均在 500ms 内，具体证据与完整 fast 状态以 TDD 记录为准。
